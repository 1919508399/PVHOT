# PVHOT 微信登录态隔离原型

该目录实现服务器常驻的微信登录态网关。内置信源库中具有已验证 `profileId` 的公众号全部通过该网关低频直拉；没有内部 ID 的公众号继续由搜狗微信公开检索监控。

## 重要边界

- 当前登录与文章列表适配器使用仍可访问的 WeWe RSS 微信读书桥 `weread.111965.xyz`。服务器默认每 12 小时刷新每个账号；请求之间至少相隔一个调度周期。
- 任一账号触发 `-2041`、429 等风控后，所有账号统一冷却 24 小时，避免连续重试延长限制。
- 原型默认不进入PVHOT生产数据；只有显式设置 `PVHOT_ENABLE_WECHAT_GATEWAY=1` 后，`fetch_wechat.js` 才会合并它的输出。
- 只保存标题、发布时间、封面和原文链接，不镜像公众号全文。
- 不尝试绕过微信的登录或频率限制。搜狗微信公开检索继续作为无需登录的降级发现通道，但只有同一浏览器会话能解析到 `mp.weixin.qq.com` 官方原文时才会入库；遇到验证页会立即停止本轮后续请求。

## 本地运行

```bash
npm install
npm run wechat:gateway
```

打开 `http://127.0.0.1:4399`。首次启动会在 `.wechat-gateway-data/admin-token` 生成管理令牌；将其粘贴到页面后生成二维码并用微信扫码。会话令牌使用本地随机AES-256密钥加密，密钥和状态目录均被Git忽略。

服务输出兼容PVHOT微信数据契约的 `wechat_gateway_items.json`。观察期内可以单独检查：

主采集任务只采用最近 8 小时内轮询过的网关健康状态，避免旧的 `ok` 覆盖本轮搜狗抓取失败；历史官方文章仍按文章发布时间正常复用。该窗口可通过 `PVHOT_WECHAT_GATEWAY_HEALTH_MAX_AGE_MS` 调整。

```bash
curl http://127.0.0.1:4399/health
```

## 观察通过后接入

在运行现有微信任务时设置：

```bash
PVHOT_ENABLE_WECHAT_GATEWAY=1 node fetch_wechat.js
```

网关条目会与搜狗结果按规范化原文链接去重。搜狗通道仍会运行并承担降级发现，不会被原型替换。
